我平时有一半时间在读文献、写综述。这件事里有两个环节特别费人：一是判断某个研究方向是不是已经被做透了、还剩多少空白；二是把不同论文里报的数字放到一起比较——因为同一个指标名，不同论文的统计口径经常不一样。

## 二、这个作品是什么

一句话：给正在读文献、写综述的学生和科研新人——打开一个网页，就能看清某个方向已经被做透到什么程度，把口径不一样的指标换算成可比的数字，并把这些判断整理成一份能直接用的研究方案。

「TopicScope · 选题雷达」是一个纯前端的科研选题工作台，七个页签：**方向雷达 / 指标口径对齐 / 文献库 / 文献综述 / 选题体检 / 研究方案 / 研究档案**。分析类计算全部在浏览器本地跑，不上传任何文献内容。

**页签一 · 方向雷达**：输入一个研究方向，它把相关文献聚成若干簇，给出覆盖度判定，并明确告诉你每个判定「不能推出什么」。每个方向卡片带一张按年发文量迷你趋势图（近三年深色高亮），「增长窗口」还是「成熟方向」一眼可见；「导师汇报」按钮一键生成 3 个备选方向的对比汇报（统计证据 + 判定依据 + 边界说明 + 代表文献 DOI），规则生成、不经模型改写，可导出 Markdown 直接拿去和导师讨论；每个备选方向带「体检这个方向」按钮，一键跳进「选题体检」做方向级评估。

![方向雷达：6 个方向聚类、覆盖判定与「不能推出什么」](https://static.tianchi.aliyun.com/userimg/1095281234536/2026-11-07/LauVxvjGhstSSdbq.png)

- 语料：内置一份离线快照，540 篇真实论文（OpenAlex 开放学术数据库），年份 2018–2026，按年均匀采样，不是拼凑出来的假数据；
- 检索溯源：页面顶部直接写明这份快照的检索式、时间范围、检索日期、来源接口和「离线快照」标记，导出时也带上；
- 分析：中文二元切分 + 英文词形归一 → TF-IDF（余弦）→ 球面 k-means（k-means++ 初始化、固定随机种子，结果可复现）；
- 判定标签（我改过一版，避免把启发式说成结论）：**高密度成熟方向 / 稳定产出方向 / 增长窗口 / 当前检索未观察到 / 证据不足**。每个判定旁边固定写一行「不能推出什么」——比如「当前检索未观察到」会明说它可能只是检索式用词或数据库覆盖造成的召回不足，不等于真实空白；
- 判定规则（界面上原样写出来）：论文数 ≤ 3 视为当前检索未观察到；占比 < 10% 且近三年占比 ≥ 60% 视为增长窗口；占比 ≥ 12% 且中位年份早于区间末尾 4 年以上、近期新增 ≤ 35% 视为高密度成熟方向；
- 拥挤度：文献占比 40% + 引用占比 30% + 顶会集中度 30%；
- 卡片默认只显示结论和关键数字，细节（方法组合、下一步、主要发表场所、代表论文）点「展开详情」才展开——第一屏不会被长文本淹没；
- 关键词共现图：28 个节点 / 87 条边，只保留提升度（lift）> 1.15 的词对，避免出现 `image—medical` 这种毫无信息量的边。

在默认快照（medical image segmentation）上，它给出的判定是：高密度成熟方向 2 个、稳定产出方向 3 个、增长窗口 1 个。

**页签二 · AI 研究方向建议（可回查）**：点「生成方向建议」，模型只拿到这个样本的数字（簇统计 + 共现词对 + 语料规模），不许自行补充事实。

- 建议里的每一个数字都带 evidenceId，前端逐条回查：能在样本里对上的标「依据可核对」，对不上的标「依据无法核对」；
- 引用了不存在的证据 ID 会被后端直接丢弃，不会出现在界面上；

**页签三 · 指标口径对齐**：把你论文或实验里的数字填进来，它算出对应指标，并给出每个指标的口径、公式和「什么时候会被误读」。

![指标口径对齐：一次算出全部指标、公式与误读提示](https://static.tianchi.aliyun.com/userimg/1095281234536/2026-11-07/PPoMqqIUVH0mBiLE.png)

- 四类任务：分类 / 分割 / 排序检索 / 回归，可直接编辑混淆矩阵、逐类别 IoU、相关性标注、真值与预测值；
- 26 个指标，每个都标注了公式、口径说明和常见误读提示；
- 支持口径换算（例如 F1 + Recall → Precision，IoU ↔ Dice）；
- **换不了的时候，它会明确说「换不了」并解释原因，而不是硬凑一个数字。** 界面上单独列了一张「换不了的口径，明确说换不了」表，把文献里最常被直接对比、实际无法互推的 5 组口径（mIoU↔mDice、Accuracy↔Balanced Accuracy、Macro-F1↔Micro-F1、Macro-F1↔Accuracy、MAPE↔SMAPE）和原因都写出来了。

最典型的例子是 mIoU → mDice：IoU→Dice 是逐类非线性变换，先平均再变换和先变换再平均结果不同，只有一个 mIoU 无法唯一确定 mDice，必须拿到每个类别的 IoU。工具把这个「换不了」和原因直接写在界面上。我认为这比一个看起来能用、其实会误导人的换算更有价值。

**页签四 · 文献库**：可按方向筛选、按被引或年份排序、设最低被引门槛，勾选后导出 Markdown 或 CSV。

![文献库：来源、证据等级、综合评分、证据卡列](https://static.tianchi.aliyun.com/userimg/1095281234536/2026-11-07/OJ4sDLkZuvyLwDIa.png)

- 每篇论文标注来源接口（OpenAlex / Crossref）、检索时间、去重键，导出时一并带上；
- **证据等级**：按「只有元数据 / 有摘要 / 已核对全文」分级，一眼看出哪些结论还没有材料支撑；
- **候选评分（六维拆解）**：问题匹配度 30、方法相关度 20、证据完整度 15、可复现程度 15、时效与趋势价值 10、用户约束适配 10，每一维都给出理由，评分偏好可切换（均衡 / 低算力 / 追新 / 开放数据）；

**页签五 · 文献综述草稿**：把当前检索样本按方向综合成综述草稿——每个方向选被引最高的 4 篇（最多 24 篇），模型只允许引用这些编号文献，正文 [n] 与文末 GB/T 7714 参考文献一一对应；按主题综合叙述（架构演进、数据效率、新兴范式……），不逐篇罗列摘要，材料不足处明说「当前材料无法判断」。这一版还给综述加了三条写作纪律：**措辞按证据强度校准**（多篇一致才用「表明/证实」，单篇只用「提示/说明」，仅机制推测用「可能」，不写无依据的最高级、不把相关当因果）、**每个主题段至少交织对比两篇工作**（不写「A 做了 X。B 做了 Y。」的流水账）、**自我对抗检查**（模型自己指出最弱的主张、未检验的前提、可能的选择性引用）。生成后前端再跑一遍本地**质量门禁**：引用门禁（[n] 是否都能对上、有没有无引用段落）、交织门禁、分寸门禁（扫描「证明/首个/唯一/最优」这类过度断言），逐条标「通过 / 存疑 / 不足」。草稿可导出 Markdown，是起点不是成品。

**页签六 · 选题体检（这个想法值不值得做）**：这是这一版新增的核心页签。把一个想法（或直接从「导师汇报」「AI 方向建议」一键带过来的方向）交给模型，像审稿人加导师一样做一套固定顺序的体检：**致命缺陷审计（早期闸门）→ 生命周期与能力匹配 → 五维评分（更高/更快/更强/更省/更广，从 5 分起步、给依据才加分）→ 范式转移探测 → 可行性风险 → 先做的三件事**。

- 新颖性不许凭空说：模型只能拿当前检索样本里编号的真实文献做对照，「没检索到」不等于「新颖」；
- 能力画像由你自报（每周小时、时间预算、编码/理论能力、算力、数据获取），模型据此判断生命周期匹配，能力未经核验这点界面上写明；
- 结论分三档：**强烈接受 · 可以启动 / 修改后接受 · 先调整范围 / 拒绝并转向 · 不建议做这个版本**；
- 前端有一道**完整性自检**：出现致命缺陷却给了「接受」会被自动降级为「拒绝并转向」，「强烈接受」但没有任何一维 ≥8 分会被降为「修改后接受」，降级原因直接写在结论旁；
- 体检报告可导出 Markdown，文末附新颖性核对文献（GB/T 7714）。

## 三、为什么做

这几个痛点是做科研时反复出现的：

- **指标口径不对齐，横向比较就是错的。** 两篇论文都写 "Dice 0.85"，一篇可能是前景平均、一篇可能是逐类平均后取平均；两篇都写 "F1"，可能一个是二分类一个是宏平均。直接放进对比表格，结论就废了。我自己在读稿时就犯过这个错。
- **判断方向有没有被做透，全靠感觉。** 搜一轮文献，看到的往往只是搜索引擎按相关度给的热门结果，不是这个方向真实的分布结构。
- **工具要么太重，要么不可信。** 很多文献分析工具要装 Python 环境、跑脚本、传数据。我想要的，是一个打开链接就能用、数据在本地、结论能追溯到具体数字的东西。
- **看了半天，最后还是得自己写方案。** 选题和写作之间是断的：判断完方向，还得把判断翻译成一份能交给导师的研究方案。

所以我给自己定的验收标准是四句话：结论必须能从界面上的数字推出来；算不出来的时候要老实说算不出来；不联网也要能用；每一条 AI 说的话都要能回查。

## 四、怎么用（5 步）

1. 打开：https://topicscope-piwbj3lryn1.qoder.zone
2. 「方向雷达」页签直接看内置快照的判定结果；想换方向就在顶部输入框输入（例如 `medical image segmentation`、`RNA-seq`），点「在线检索」。在线检索走 OpenAlex 开放接口，不填 key 也能用，只是配额更小；在「设置」里填自己的 OpenAlex API key 可以提高配额（key 只保存在你自己浏览器的 localStorage 里，不会上传，也不会进入站点文件）。
3. 点「生成方向建议」得到可回查的研究方向；点任意方向卡片上的「查看该方向的 N 篇文献」跳到「文献库」；在文献库里打开「证据卡」逐字段核对。
4. 切到「指标口径对齐」页签：填入你的混淆矩阵（或二分类 TP/FP/FN/TN，或逐类别 IoU，或相关性标注，或真值与预测值），就能一次看到全部指标、公式和误读提示；再用「口径换算台」把论文里报的数字换成可比的数字，换不了的地方会给出原因。
5. 切到「文献综述」页签，基于当前样本生成综述草稿并导出（[n] 引用对应 GB/T 7714 参考文献，附质量门禁与自我对抗检查）；切到「选题体检」页签，写一段想法（或从导师汇报/AI 建议一键带入）并填能力画像，得到三档结论的体检报告；切到「研究方案」页签填约束生成 15 节方案并导出 Markdown；切到「研究档案」保存当前会话，之后可以随时回到这个研究现场。

## 五、用 Qoder 做出来的过程

这个项目从想法到上线都由 Qoder 参与完成。我的做法是：我定方向、划验收标准、找出问题并给修改意见，Qoder 负责实现和自测。下面按实际推进顺序说明。

**第 1 步：先把「选题」拆成两个可验证的动作（我提出，Qoder 落地）**

我最初的想法太笼统，Qoder 帮我把它压成了两个能验收的动作：能不能从一批文献里看出方向分布并给出空白判断；能不能把一个指标换算成另一个口径。这两条定下来之后，页面的信息架构和后面的验收标准都清晰了。

**第 2 步：指标模块先做，并配一份独立自检（我验收，Qoder 实现）**

指标口径是整个作品的信任基础，所以放在最前面。我给 Qoder 的要求是：每个指标都要有公式和口径说明，能换算的要能换算，换算不了的要写明原因。

这里抓到一个真 bug：多分类 MCC 的实现算出了 57.9 这种远超 [-1, 1] 的值。我让 Qoder 去核对权威实现，查了 scikit-learn 主分支源码，把公式换成 Gorodkin 形式（`cov_ytyp / √(cov_ypyp · cov_ytyt)`，二分类时退化为标准 MCC）。随后我用 Python 独立写了一份参考实现放在仓库的 `dev/` 目录下，它只共享数学定义、不共享代码路径，把期望值固化成 50 个用例。站点里内置了「自检 50 / 50 通过」面板，点开能看到每个用例的名字、期望值和实际值。

**第 3 步：数据源可行性实测（我要求先测再写）**

在动手写抓取逻辑之前，我先让 Qoder 逐个实测候选数据源：arXiv 没有 CORS 头、Semantic Scholar 返回 429、DBLP 有反爬校验，最后选定 OpenAlex 与 Crossref（两者都返回 `Access-Control-Allow-Origin: *`）。这个结论直接决定了整个作品可以做成**纯前端、无后端、零部署成本**的形态。

**第 4 步：离线快照与在线检索分开做（Qoder 实现，我给方向）**

第一版快照按被引量抓取，结果被 2026 年的新论文淹没（260/460 篇来自同一年）。我提出改成按年分桶、每年固定配额，重新抓取后得到 540 篇、2018–2026 年分布均匀的语料。

关于 API key，我一开始就定了硬约束：**不打包进站点**。key 只作为用户可选输入保存在浏览器 localStorage，只有用户主动点「在线检索」时才随请求发出。发布后我逐项验证过：构建产物 JS/CSS、快照 JSON、线上页面文本里都搜不到这个 key。

**第 5 步：分析层推翻重做两轮（我发现问题，Qoder 重写）**

- 第一版分词过度（`-ing` / `-ed` 规则把 "semi-supervised" 砍成 "semi-supervis"、"diagnosis" 砍成 "diagnosi"），聚类名完全不可读。改为只做复数归一，并加了一份领域通用词停用表（method / approach / framework / intelligence 等）。
- 第二版共现图退化成 `image—medical` 这种无意义边。改为加文档频率上限（45%）、只保留 lift > 1.15 的边、提高最小共现次数后，图才变成有信息量的结构：`adaptation—few-shot` 提升度 2.39、`brain—tumor` 3.54、`classification—detection` 1.79。

**第 6 步：判定口径重写——从「说结论」改成「说边界」（我提出，Qoder 重做）**

这是我对成品影响最大的一次返工。原来只有「已做透 / 成熟 / 潜在空白」三个标签，读起来像结论。我要求改成五档并强制每张卡片带一行「不能推出什么」，把「当前检索未观察到」和「证据不足」单独拆出来，同时在界面上把判定规则原文写出来。这条改完之后，界面才真正像一个研究工具而不是一个结论生成器。

**第 7 步：加证据链与研究方案（我给设计稿，Qoder 实现）**

我写了一版设计稿，把「看方向」扩成一条完整链路：检索快照与来源溯源 → 方向判定 → 可回查的 AI 建议 → 文献库与候选评分 → 逐字段核对的论文证据卡 → 15 节研究方案生成器 → 研究档案。Qoder 按稿实现，并加了 evidenceId 机制：模型每引用一个数字都要带 ID，前端逐条回查，对不上的标「依据无法核对」，不存在的直接丢弃。

**第 8 步：模型 key 从源码移除，改用服务端 Secret（Qoder 实现，我验收）**

第一版 AI 功能我把模型 key 直接写在了函数源码里。我要求删掉，改成读 Qoder Sites 的服务端 Secret（`QWEN_API_KEY`），并检查了构建产物、函数目录和线上页面都搜不到这个字符串。Secret 的值由我在 Qoder Desktop 的站点设置里填，代码里只保留 Secret 名。

**第 9 步：UI 做一次学术期刊风格的统一重做（Qoder 实现，我验收）**

原来的界面能用但偏工具感。我让它按学术期刊的视觉规范重做：纸白底色、衬线标题、正文无衬线、表格用小号大写字表头 + 细横线、图表放进带图注的 figure 面板、焦点态可见、对比度按 WCAG AA。改完之后整个站点看起来像一篇论文的配套材料，而不是一个后台管理页。

**第 10 步：部署并开放公网（交给 Qoder）**

最后把构建产物通过 Qoder Sites 发布，再把访问权限从「仅自己可访问」改成「任何人可访问」。发布后做了匿名访问验证：页面返回 200、快照 540 篇、七个页签正常、Canvas 共现图有实际像素渲染、自检面板 50/50 通过。

**第 11 步：把开源科研 Skills 的方法论迁移进来（我选材，Qoder 移植并接线）**

我找到开源项目 HKUSTDial/Supervisor-Skills（CC-BY-4.0），让 Qoder 通读后把里面真正有用的方法论移植成产品功能，而不是照搬提示词：idea-evaluator 的「致命缺陷→生命周期匹配→五维评分→范式探测→风险→结论」固定流程做成了「选题体检」页签，并加了前端完整性自检防止结论和分数自相矛盾；deep-research 的措辞分寸、交织对比、自我对抗检查做进了综述；tech-paper-template 的逻辑链互锁做进了研究方案；手册里的审稿人视角做成了证据卡速查。所有改编都在界面和导出 Markdown 里保留了 CC-BY-4.0 署名。新颖性核对一律落到当前样本里编号的真实文献，不允许模型凭空断言「没人做过」。

## 六、限制与不足（说明白，免得误导评委）

- 离线快照只覆盖 `medical image segmentation` 一个检索式。换别的方向必须走在线检索，且需要自己的 OpenAlex key（离线快照是静态 JSON，更新需要重新抓取）。
- 聚类是无监督的，簇名取自质心词，人工看仍有错分。例如 `counting · processing` 这 4 篇其实是微生物计数与生物量估计，跟主线医学分割的关系很弱——这说明无监督聚类在长尾语料上会碎掉。
- 覆盖判定规则（≤3 篇为当前检索未观察到、占比与年份阈值等）是我自己定的启发式，不是这个领域的共识，也没有经过专家校验；它只能当作「值得多看一眼」的线索，不能当作结论。
- 共现统计基于标题、关键词、主题与摘要，不读全文，也不区分词义。
- AI 建议和研究方案由模型生成，数值依据虽然可以逐条回查，但**研究方案的可行性和新颖性没有被验证过**；它是一份结构化草稿，不是经过同行评议的结论。
- **选题体检的结论同样是模型生成的启发式判断，不是真实评审**：五维评分的起步分与加分规则、生命周期窗口、范式探测都是我移植并简化的框架，能力画像靠你自报、未经核验；新颖性只对照当前检索样本，样本之外的文献它看不到，所以「拒绝并转向」也可能只是样本覆盖不足。请把它当作一份结构化的第二意见，最终判断仍在你和导师手里。
- 选题体检、综述写作纪律、方案逻辑链检查、审稿人速查改编自 HKUSTDial/Supervisor-Skills（CC-BY-4.0），已按要求在界面与导出中署名；改编做了简化，不等同于原项目的完整评估。
- 六维候选评分里的权重是我定的启发式，不是学界共识；不同人给同一篇论文的评分会不一样。
- 指标模块做的是口径换算与解释，不处理样本级曲线、置信区间和统计显著性；它不会告诉你 A 方法是不是「显著地」比 B 好。
- 站内数据处理在浏览器本地完成，但检索本身会把你的检索词发给 OpenAlex / Crossref；文献内容不上传。
- 站点页面右下角有平台依法加注的「Made with Qoder」生成式 AI 标识，我按规则保留未去除。
